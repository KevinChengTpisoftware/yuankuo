# 員郭個別化復健系統開發計畫

## 1. 計畫目的

依據 `01-員郭--復健病房願望蒐集與照護計畫數位化.md` 與 `02-員郭第二次需求訪談.md`，製作一套可獨立開啟、適合 11 月報告錄影與現場展示的個別化復健系統 HTML Demo。

本階段重點不是建置正式醫療資訊系統，而是將核心臨床流程與生活功能庫管理轉成可操作的介面，讓使用者能理解：病人的生活願望如何被蒐集、拆解、排序，最後形成可由專業人員審核的照護計畫，並在病患端呈現生活功能解鎖進度。

## 2. 第一階段範圍

### 2.1 納入範圍

1. 病人／家屬／護理師使用的願望蒐集流程。
2. 願望大分類選擇與分類細項圖卡選擇。
3. 自訂「其他願望」文字輸入。
4. 語音輸入的展示型互動，若瀏覽器不支援則以文字補充替代。
5. 護理端暫存草稿與目前流程狀態提示。
6. 願望對應生活功能項目清單，包含星等與關聯說明 Popover。
7. 生活功能項目拖放至四象限，支援重新放置與重設。
8. 依四象限與星等產生展示用短、中、長期照護計畫草稿。
9. 治療師人工編輯照護計畫文字、增加目標、暫存與確認送出等展示型互動。
10. 病患端「生活功能解鎖護照」，呈現已解鎖、進行中、下一個挑戰與尚未開始。
11. 以員郭醫院 Logo 作為系統品牌識別，左上角固定顯示。
12. 桌面、平板與手機尺寸的響應式版面。
13. 完整 150 項生活功能後台管理，包括查詢、篩選、新增、編輯、停用、關聯檢視與異動紀錄展示。
14. 生活功能庫 Excel/CSV 匯出、上傳、欄位比對預覽、錯誤攔截與確認匯入。
15. 六個願望大分類各自建立可展示的細項圖卡資料，並支援後台調整圖卡與生活功能的關聯。

### 2.2 本階段不納入

1. 真實登入、角色權限與個資驗證。
2. PAC 即時 API、Webhook 或院內系統回寫。
3. 真實 AI API、語音轉文字後端與模型訓練。
4. 真正的資料庫、雲端儲存與跨裝置同步。
5. 真實復健器材、QR Code 與訓練數據串接。
6. 正式病歷、醫療決策或自動核准功能。
7. 真實多人同時編輯與伺服器端異動鎖定。

以上功能保留在後續版本規劃，不以假互動冒充正式醫療系統能力。

## 3. 目標使用情境

### 3.1 展示用個案

使用預設 Demo 個案：陳阿公，72 歲，床號 B03-1。個案資料會預先填入，但可透過「編輯個案」修改姓名、年齡、床號、入院天數、照顧者與診斷等展示欄位。預設願望包含：

- 去活動中心唱歌
- 和老朋友下棋／打牌
- 自己拿湯匙吃飯

介面提供清楚的「展示個案」標示，避免使用真實個資；修改後的內容僅儲存在本機瀏覽器。

### 3.2 主要操作流程

```text
願望蒐集首頁
  → 選擇願望大分類
  → 選擇 1～3 個具體願望
  → 輸入其他補充／暫存
  → 願望展開與生活功能清單
  → 拖放至四象限
  → 產生短、中、長期照護計畫草稿
  → 治療師編輯與確認
  → 生活功能解鎖護照
```

## 4. 頁面與功能設計

### 4.1 全域框架

- 左上角顯示 `員郭醫院_logo.png`，使用相對路徑載入。
- 標頭顯示系統名稱、目前流程階段、Demo 個案資訊。
- 提供返回上一階段、首頁與目前草稿狀態提示。
- 以高對比、較大字級、寬點擊區域支援長者與平板操作。
- 使用一致的色彩語意：綠色代表醫療品牌與完成、藍色代表互動與治療、琥珀色代表進行中、灰色代表尚未開始。
- 病人訪談首頁只顯示個案資訊、六大願望分類與「離開／稍後再選」「護理端暫存草稿」；護照、進度與後台不直接干擾首次選擇。
- 訪談首頁同步顯示目前已選總數、已選願望清單，以及六大分類各自的已選數量；已選願望可直接在首頁點擊取消，避免使用者在內頁與分類間迷路。
- 已選願望以可換行的橫向標籤排列，並提供首頁「一鍵清除」功能。

### 4.2 頁面一：願望大分類選擇

- 顯示「請點選您最想加強的方向」。
- 提供六個大分類：自我照顧、生活起居、工作職場、運動鍛鍊、外出移動、休閒社交活動。
- 每張分類卡顯示白話說明與圖像化符號。
- 提供「離開／稍後再選」與「護理端暫存草稿」。
- 點擊分類卡後進入該分類的願望圖卡頁。
- 首頁提供「確定選取，展開願望分析 →」；已有選取時可直接進入四象限分析，未選取時提示先選擇願望。
- 核心流程統一使用上方二態步驟列（`●` 目前步驟、`○` 其他步驟），頁面底部提供唯一的「返回上一步／繼續下一步」導覽。
- 護理／治療師功能集中於單一工作區入口，不與病人訪談首頁的六大分類混在一起。
- 六個分類均先提供 11 個具體願望與 1 個「其他」卡片，讓分類頁具有一致的展示密度。

### 4.3 頁面二：願望圖卡選擇

- 以卡片呈現具體願望，不限制選取數量；再次點擊已選卡片即可取消，支援病人重新思考與調整。
- 至少提供運動鍛鍊分類的 11 項範例與 1 項「其他」。
- 以兩頁呈現 11+1 項，顯示分頁位置與已選數量。
- 已選卡片有清楚的選取狀態與星號提示。
- 「其他」開啟文字輸入面板，可留下補充願望。
- 提供語音輸入展示按鈕；瀏覽器不支援時顯示文字輸入替代說明。
- 完成後進入願望展開頁。

### 4.3.2 圖像素材策略

- 優先使用 OpenMoji 的彩色 SVG/PNG 作為動作提示圖示。OpenMoji 官方標示採 CC BY-SA 4.0，需在頁面或素材說明中保留來源與授權資訊。
- 若需要完整人物情境插畫，評估使用 unDraw；其官方授權允許一般專案免費使用且不要求署名，但不應將素材重新打包成素材庫或用於 AI 訓練。
- 所有選定圖片下載至專案本地 `assets/wishes/`，不直接依賴外部圖片網址，確保離線錄影與現場展示穩定。
- 圖片命名採分類與序號，例如 `exercise-01-walk.svg`、`self-care-01-eating.svg`，並在資料物件中保留來源、授權與替代文字。
- 若開放素材無法準確表達「長者復健情境」，先以一致風格的圖示搭配中文文字，不使用未確認授權的網路圖片。

### 4.4 頁面三：願望展開與四象限決策

- 左側顯示已選願望與其對應的生活功能項目。
- 每個功能項目顯示代碼、白話名稱、星等與目前放置狀態。
- 功能清單只顯示目前選取願望的關聯項目；星等依目前願望重複命中次數計算，並依命中次數由高至低排序。1 個命中為一星、2 個命中為二星、3 個以上命中為三星。
- 點擊問號開啟「生活功能關聯星等說明」Popover。
- 右側提供四個放置區：
  - 第一象限：高意願／高重要性，核心優先
  - 第二象限：高意願／低重要性
  - 第三象限：低意願／低重要性
  - 第四象限：低意願／高重要性，基礎維持
- 支援滑鼠拖放與觸控裝置的替代操作：先點選生活功能項目，再點擊目標象限。
- 已放置項目可移除，也可直接移動至其他象限。
- 顯示各象限項目數與待放置數量。
- 每個象限可累積放置多項生活功能，不因後放項目覆蓋先前項目。
- 提供重設位置、暫存分析進度與產生照護計畫草稿。

### 4.5 頁面四：照護計畫草稿與人工審核

- 左側唯讀顯示四象限落點、星等與 PAC 初評展示資料。
- 右側分為長期、中期、短期三段目標。
- 預填展示用草稿文字，並保留可編輯的文字區域。
- 支援新增目標、刪除目標、重新產生展示草稿與暫存。
- 清楚標示「展示用 AI 草稿，尚未回填 PAC」。
- 確認送出按鈕只更新前端狀態與護照資料，不進行真實外部系統寫入。

### 4.6 頁面五：生活功能解鎖護照

- 以病患可理解的語言呈現，不顯示 PT/OT/ST、星等或內部代碼。
- 顯示願望摘要、整體進度與解鎖比例。
- 以卡片呈現四種狀態：已解鎖、進行中、下一個挑戰、尚未開始。
- 顯示完成日期或目前進度，例如「已完成 2/5 次」。
- 顯示治療師今日鼓勵文字。
- 提供查看完整願望地圖、通知家人／照顧者與聯絡護理站等展示按鈕。
- 參考網站：`https://yuankuo-re.netlify.app/` 的六大生活領域、階段任務、0/150 達成率與卡片化護照概念；本系統改以個別化復健願望、功能任務與臨床團隊鼓勵呈現。
- 護照提供獨立入口、六大領域切換、150 項任務卡、任務狀態循環（尚未開始／進行中／已解鎖）、願望清單與動態達成率；首頁與護照共用同一份解鎖狀態。

### 4.7 頁面六：生活功能成就庫後台管理

- 提供 150 項生活功能資料表，欄位包含分類、代碼、名稱、專業領域、來源標記、狀態、PAC/量表門檻與 AI 目標建議片語。
- 提供分類、專業領域、啟用狀態與關鍵字篩選。
- 提供新增、編輯、停用與關聯檢視；預設標準項目不可實體刪除。
- 自訂項目未被引用時可刪除；已有願望或病患引用時只能停用。
- 提供願望圖卡與生活功能的一對多關聯設定，可調整排序與預設權重。
- 顯示目前資料版本、項目總數、預設標準／自訂項目數與最後修改資訊。
- 提供展示用異動歷程，記錄操作類型、操作人員、時間與影響筆數。

### 4.8 頁面七：生活功能庫 Excel/CSV 匯入匯出

- 匯出可選目前篩選結果或完整資料庫。
- 支援 `.csv` 與 `.xlsx` 下載，欄位包含生活功能資料與自動計算的願望關聯摘要。
- 匯入時以「項目代碼」作為唯一比對鍵，預覽新增、修改、無變化與被拒絕列。
- 預設標準項目不可被改成自訂來源或實體刪除；違規資料列顯示攔截原因。
- 關聯願望清單與關聯數為衍生唯讀欄位，匯入時忽略檔案中的修改值。
- 在使用者按下「確認匯入」前，不寫入目前的前端資料狀態。
- 匯入完成後更新版本與異動歷程展示資料。

### 4.9 操作紀錄與測試整合

- 每個主要操作都寫入操作紀錄：編輯個案、選擇分類、選取願望、暫存、象限放置、產生／確認照護計畫、後台 CRUD、匯入匯出與頁面切換。
- 操作紀錄在「操作紀錄」頁面呈現，並以 `localStorage` 保存，方便 Demo 時說明系統可追溯性。
- 使用 Playwright CLI 逐步操作並驗證主要流程，操作結果與錯誤狀況納入驗收紀錄；Playwright 不作為正式系統的資料儲存機制。

## 5. 技術方案

### 5.1 實作形式

- 以單一 `index.html` 作為可直接開啟的 Demo 入口。
- CSS 與 JavaScript 優先內嵌於 HTML，降低展示時的檔案依賴與啟動門檻。
- Logo 使用同資料夾的 `員郭醫院_logo.png`。
- 不引入需要安裝或編譯的框架，確保可直接以瀏覽器開啟。
- Excel `.xlsx` 使用本地化的 SheetJS 瀏覽器版檔案；CSV 使用原生 Blob 產生與 File API 解析，避免把 Excel 功能降級成僅改副檔名。
- 若本地化 SheetJS 檔案尚未放入專案，開發時先建立清楚的依賴檔名與錯誤提示，不以未告知的 CDN 連線作為唯一方案。

### 5.2 前端狀態

- 使用單一前端狀態物件保存目前頁面、個案、選取願望、功能項目位置、照護目標與護照進度。
- 使用 `localStorage` 保存暫存草稿，讓重新整理頁面後仍可恢復展示進度。
- 所有資料為明確標示的 Demo fixtures，不宣稱是真實臨床資料。
- 將畫面切換、資料更新、象限放置與草稿產生集中管理，避免每個頁面各自複製資料邏輯。
- 將 150 項生活功能、願望圖卡、關聯資料與匯入預覽資料分開管理，避免後台表格與前台畫面複製同一份資料。
- 將操作紀錄集中由 `log()` 寫入，所有頁面共用同一種紀錄格式，避免各頁面自行建立不同的稽核格式。

### 5.3 響應式策略

- 桌面版採雙欄工作區，適合治療師操作。
- 平板版保留大卡片與雙欄優先級分析，但縮減間距。
- 手機版將雙欄改為上下堆疊，拖放改以點擊選擇與目標象限按鈕操作。
- 所有主要按鈕需具備清楚文字，不只依賴圖示。

## 6. 互動與防呆規則

1. 願望可選取任意數量；未選取時不可進入下一步，需顯示原因。
2. 「其他願望」若已開啟但未輸入內容，不納入正式選取清單。
3. 未放置的功能項目可保留，不能阻擋產生草稿，但需在頁面上顯示未放置數量。
4. 同一功能項目只能存在一個象限，重新放置時自動從原象限移除。
5. 星等計算以目前選取願望為範圍，不使用與本次個案無關的預設命中數；3 個以上命中即顯示三星，不要求所有選取願望都命中。
6. 尚未確認的照護計畫一律標示為草稿。
7. 重新產生草稿前，顯示會覆蓋目前草稿內容的提示。
8. 重設象限前顯示確認提示，避免誤清除治療師配置。
9. 返回上一頁時保留目前狀態，不直接清除已選內容。
10. 所有會改變資料的按鈕在完成後顯示明確的成功狀態。
11. 預設標準項目不可刪除，只能停用；自訂項目是否可刪除依引用狀態判斷。
12. 匯入資料先進入預覽狀態，只有確認後才套用新增與修改。
13. 匯入資料缺少代碼、代碼重複或欄位格式錯誤時，列入被拒絕清單並保留原因。

## 7. 視覺與可用性驗收

- Logo 位於頁面左上角，桌面與手機版皆不變形、不被裁切。
- 首頁分類卡在平板上可一眼辨識，文字不過小。
- 主要互動元件具備 hover、focus、selected 與 disabled 狀態。
- 色彩對比足以閱讀，狀態不只以顏色區分，也搭配文字或圖示。
- 版面在 1280px 桌面、768px 平板、390px 手機寬度下不出現水平溢出。
- 對長者操作的按鈕、卡片與輸入區保留足夠點擊面積。
- 文字採繁體中文與臺灣醫療情境用語。
- 圖卡圖片具有明確來源、授權與替代文字；離線開啟 HTML 時圖片仍可正常顯示。
- 後台可實際完成至少一筆新增、一筆編輯、一筆停用、一筆關聯調整，以及一次 CSV 與一次 XLSX 匯出／匯入預覽。
- 預設個案資料會顯示，且修改後標頭、護照與操作紀錄會同步更新。
- Playwright CLI 可完成從願望分類、願望選取、四象限、照護計畫到護照的連續操作，且頁面 Console 無錯誤。

## 8. 驗收情境

### 情境 A：病人完成願望蒐集

1. 開啟首頁，看到 Logo 與陳阿公個案資訊。
2. 進入「運動鍛鍊」，跨兩頁選擇 1～3 個願望。
3. 輸入一段「其他願望」或補充文字。
4. 點擊確認，進入願望展開頁，且已選資料仍存在。

### 情境 B：治療師完成四象限分類

1. 查看已選願望與對應功能項目。
2. 開啟星等說明 Popover 並關閉。
3. 將功能項目拖曳或以觸控替代操作放入不同象限。
4. 確認統計數字、項目狀態與排序同步更新。
5. 重新放置一項目，確認不會重複出現在兩個象限。

### 情境 C：治療師審核照護計畫

1. 從四象限頁產生照護計畫草稿。
2. 查看長、中、短期目標與生成依據。
3. 修改至少一段目標並新增一項短期目標。
4. 暫存後重新整理，確認草稿可恢復。
5. 確認送出後，進度進入病患護照展示頁。

### 情境 D：病患查看生活功能護照

1. 查看願望摘要與整體進度。
2. 確認四種狀態卡片都有清楚文字。
3. 查看今日鼓勵與完整願望地圖入口。
4. 在手機寬度下確認版面可閱讀與操作。

### 情境 E：管理員維護 150 項生活功能庫

1. 以分類與關鍵字篩選資料。
2. 編輯一筆預設標準項目，確認可修改允許欄位。
3. 嘗試刪除預設標準項目，確認系統阻擋並提示只能停用。
4. 新增一筆自訂項目並與願望圖卡建立關聯。
5. 停用該項目後，確認前台不再提供新選取，但歷史資料仍保留。

### 情境 F：管理員匯出與匯入生活功能庫

1. 匯出目前篩選結果為 CSV 與 XLSX。
2. 上傳含新增、修改、無變化與違規資料的測試檔。
3. 確認匯入預覽正確分組並顯示攔截原因。
4. 確認預覽期間正式資料不變。
5. 按下確認匯入後，確認資料、版本與異動歷程同步更新。

### 情境 G：個案資料與操作紀錄

1. 確認首頁預設顯示陳阿公、72 歲、B03-1。
2. 修改姓名或床號，確認標頭與護照頁同步更新。
3. 開啟操作紀錄，確認修改個案、頁面切換與主要操作均有時間與內容。
4. 使用 Playwright CLI 重跑主要流程，確認每一步均能被記錄。
