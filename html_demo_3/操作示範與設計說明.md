# 第一部分：設計理念與資料流程

## 1. 核心理念：以病人為核心，階段決定路徑

舊設計把「PAC 病人」當成固定身分，新設計改為：

- **病人只有一份主檔**（獨立系統 ID），熟識人資料也只有一份。
- **照護階段**（PAC／復健病房／一般復健／OPD）是病人身上「會隨時間改變的屬性」，每次變更都新增一筆歷程，不覆蓋舊的。
- **階段只決定「後面要不要做復健計畫」**，不決定能不能用任務：150 項生活復健任務所有人都可使用。

## 2. 整體資料流程

```
病人主檔（系統 ID／病歷號／PAC ID／信祥 ID）
   │
   ├─ 照護階段歷程（可多筆，保留歷史）
   │
   ▼
熟識人（跨專業共同填寫：PT／OT／ST／營養／醫師／護理／社工）
   │
   ▼
願望圖卡（28 張 + 自訂）──第二層文字 = 患者預期目標
   │
   ▼
願望象限（病人拖曳：重要性 × 急迫性）──決定願望先後順序
   │
   ▼
生活復健任務（150 項，所有階段皆可選）
   │
   ▼
目前階段是否啟用復健計畫？
   ├─ 否（一般復健／OPD）→ 儲存本次任務紀錄，流程結束
   └─ 是（PAC／復健病房）→ 復健計畫
          預期目標 → 長期目標 → 短期目標 → 任務分短/長期 → 預後目標
          │
          ├─ 每次儲存 = 新版本（舊版保留，需填原因）
          ├─ 約每 2～3 週檢討
          └─ 每 80 天重新修訂（留 audit log）
   │
   ▼
生活功能護照
   ├─ 1.0：150 項任務闖關（銅／銀／金盃、徽章、協助夥伴）
   └─ 2.0：個人照護計畫（顯示願望、目標、任務進度）
```

## 3. 關鍵設計決策

| 議題 | 作法 | 原因（來自甲方說明） |
|---|---|---|
| 階段變更 | 新增歷程，不覆蓋 | 同一人可能病房 → 一般復健 → OPD → 再進 PAC |
| 是否需要復健計畫 | 後台依階段設定開關；個別病人可由治療師選擇產出 | 一般復健／OPD 目前不強制 |
| 任務長短期 | 不在後台設定，在個別病人的計畫中由治療師決定 | 同任務對不同病人難度與時間點不同 |
| 計畫修訂 | 每次儲存產生新版本，需填原因，可看差異 | 每 2～3 週檢討、不直接覆蓋 |
| 預後目標 | 預設片語（可點選再修改）＋ AI 草稿 | 治療師直接點，再自己改 |
| 熟識人 | 每職類獨立填寫區，保留填寫者、時間、歷次內容 | 多人共同使用，非一個大文字框 |
| 識別碼 | 系統 ID 獨立不變，另有病歷號、PAC、信祥欄位 | 未來串接 HIS／PAC 不需重做主檔 |
| 稽核 | 重要操作寫入操作紀錄（誰、何時、做了什麼） | 80 天修訂、計畫版本需留記錄 |

## 4. 主要資料結構（展示版）

```
病人 patient
├─ id、name、sex、age、bed、diagnosis、caregiver、decider
├─ mrn（病歷號）、ext.pac、ext.xin   ← 串接預留
├─ stages[]      { stage, from, to, note }            階段歷程
├─ fam{職類}     { 各欄位…, _by, _at }                 熟識人現況
├─ famHist[]     { tab, by, at, data }                 熟識人歷次內容
├─ wishes[]、custom[]、place{願望→x,y}                 願望與象限位置
├─ sel[]                                               已選任務 ID
├─ tasks{任務ID} { st, partner, at }                   護照進度
├─ records[]     { at, by, stage, ids }                不需計畫階段的任務紀錄
└─ plans[]       { ver, at, by, type, reason, snap }   計畫版本
                  snap = { expect[], long[], short[], prog[], term{任務→short/long} }

全域：stageCfg（各階段是否啟用計畫）、phrases（預後片語）、taskOff／taskEdit（任務庫維護）、logs（操作紀錄）
```

## 5. 展示版與正式版的差異（請先說明）

- **資料存本機瀏覽器**，換電腦或清除瀏覽器資料就消失；正式版需後端資料庫。
- **AI 產生預後目標為規則式示範**（依預期目標、願望所需輔具、照顧者協助組句），並非真的接 AI 模型。
- **與 PAC、信祥的串接尚未實作**，只預留識別碼欄位。
- 願望示範影片目前只有「食」領域 4 張；音樂預設對應為暫定。
- 熟識人各職類欄位為示範，需各專業確認。

## 示範一：陳阿公（PAC）— 完整流程

**目的**：展示從主檔到護照的完整路徑與版本化計畫。建議 6～8 分鐘。

| 步驟 | 操作 | 要講的重點 |
|---|---|---|
| 1 | 選「陳阿公」，停在 **① 個案主檔** | 流程圖最後一格是「是 → 短期＋長期＋定期檢討」；下方識別碼區預留 PAC／信祥對應 |
| 2 | 看右側「照護階段歷程」，再按 **變更照護階段**（可取消） | 他從復健病房轉 PAC，舊階段保留，不蓋掉 |
| 3 | 進 **② 熟識人**，看「跨專業總覽」 | 8 個職類都有填寫；點「物理治療 PT」看歷次內容（有 2 筆） |
| 4 | 把操作身分切成「職能治療師」，進 OT 分頁修改一欄後儲存 | 儲存後多一筆歷次內容，帶填寫者與時間 |
| 5 | 進 **③ 願望圖卡**，點第一張卡的「詳情」 | 第二層文字就是「患者預期目標」；食領域有示範影片；已選 3 個願望 |
| 6 | 按 **Aa 大字**，再按「📖 大圖書本閱讀」翻幾頁 | 給長者看的一頁一圖版面，可直接在這裡選願望 |
| 7 | 進 **④ 願望象限** | 已放好：湯麵願望在 Q1（重要且急迫）、行走願望在 Q2、唱歌願望在 Q3；可拖曳調整，下方排序結果會跟著變 |
| 8 | 進 **⑤ 生活復健任務** | 已依願望帶入任務；可試「一鍵帶入建議任務」；強調長短期不在這裡決定 |
| 9 | 進 **⑥ 復健計畫** | 見下方細項 |
| 10 | 進 **生活功能護照** | 1.0：已解鎖 7 項，點任務卡可改狀態與協助夥伴，解鎖會有慶祝畫面；2.0：看個人照護計畫與短／長期任務進度 |

**步驟 9 細項（重頭戲）**

1. 頂部「檢討與修訂提醒」：最新版 v2（9/30），再按 **「+80 天」** 快轉，會出現「80 天修訂」提醒。
2. ① 患者預期目標：由願望第二層文字自動帶入，依象限排序，可修改。
3. ④ 任務短／長期：逐項切換短期／長期，示範「由治療師決定」。
4. ⑤ 預後目標：先點上方預設片語加入一條，再按 **「✨ AI 依預期目標產生」**，看 AI 草稿（含輔具與照顧者協助），可直接修改。
5. 按 **「儲存為新版本（v3）」**，類型選「80天修訂」並填原因。
6. 到下方版本歷程，按 v3 的「檢視內容與差異」，看「已變更」標記。
7. 到 **後台管理 → 操作紀錄**，看到本次儲存留有紀錄。
8. 結束後按「還原」把快轉歸零。

## 示範二：林阿嬤（一般復健）— 任務儲存即結束

**目的**：展示同一套任務，但不需建立復健計畫。建議 2 分鐘。

1. 切換病人為「林阿嬤」，個案主檔流程圖最後一格是灰色的「否 → 任務儲存即可」。
2. 上方導覽的「⑥ 復健計畫」帶 🔒；點進去顯示「目前階段不需要復健計畫」。
3. 回 **⑤ 生活復健任務**：任務可正常選取；下方按鈕是 **「儲存本次任務紀錄（流程結束）」**，不是「建立復健計畫」。
4. 按儲存，下方出現「歷次任務紀錄」。
5. 補充：若治療師評估仍需要，可按 **「治療師選擇產出復健計畫」**（會跳確認並寫入紀錄）。

**重點話術**：「一般復健與 OPD 目前不強制計畫，選完任務就完成該次紀錄；但治療師保有選擇權。」

## 示範三：王先生（OPD）— 階段轉換歷程

**目的**：展示照護階段改變、舊類別不被覆蓋。建議 2 分鐘。

1. 切換為「王先生」，看 **① 個案主檔** 右側時間軸：一般復健（9/1～9/24，已結束）→ OPD（9/25 起，目前）。
2. 按 **「變更照護階段」**，選「PAC」，備註「再次入院」，確認。
3. 時間軸新增 PAC，OPD 自動標為結束；流程圖變成「需建立復健計畫」，⑥ 解鎖。
4. 到 **後台管理 → 操作紀錄**，看到「變更照護階段」的紀錄。
5. 熟識人頁只有主治醫師有填寫，說明「各職類可逐步補上，不需一次填完」。

**重點話術**：「病人還是同一人、熟識人資料還是同一份，只是階段改變；系統不把舊類別蓋掉。」

> 示範完想回到原狀，請使用「重設為初始示範資料」。

## 示範四：黃奶奶（復健病房）— 80 天修訂與版本

**目的**：展示逾期提醒與版本歷程。建議 3 分鐘。

1. 切換為「黃奶奶」，進 **⑥ 復健計畫**。
2. 頂部「檢討與修訂提醒」直接顯示：定期檢討已逾期、**80 天修訂**「本輪已滿 87 天」（不需快轉）。
3. 看版本歷程：v1（7/10 初版）、v2（8/1 定期檢討），按 v2「檢視內容與差異」，看哪些區塊「已變更」。
4. 操作身分切為「職能治療師」，修改短期目標一行，再按「儲存為新版本（v3）」，類型選「80天修訂」。
5. 不填原因直接儲存 → 系統會擋下，要求填原因；填完後成功。
6. 回頂部提醒：80 天已重新計算。
7. 到 **後台管理 → 操作紀錄** 看 v3 的紀錄。

**重點話術**：「每次修訂都留下新版本與原因，舊版永遠可看，這就是 audit log。」

# 第三部分：補充示範

## 後台管理（約 2 分鐘）

- **生活任務庫**：150 項，可搜尋、編輯、停用（不實體刪除）；沒有長短期欄位，是刻意設計。
- **階段設定**：勾選各階段是否啟用復健計畫（例如把 OPD 勾起來，所有 OPD 病人的 ⑥ 立刻解鎖）。
- **預後片語**：每行一句，儲存即生效，回復健計畫可看到新片語。
- **操作紀錄**：所有重要操作的稽核軌跡。
- **匯出**：任務庫 CSV、全部資料 JSON。

## 長者大字模式與大圖書本

- **Aa 大字**：整頁放大，任務圖約 170px。
- **📖 大圖書本閱讀**：一頁一個任務／願望，圖與字最大化，左右大箭頭、可滑動或按方向鍵；護照中可直接按「進行中／已解鎖」。

## 常見提問與回答

| 提問 | 回答 |
|---|---|
| 資料會不會遺失？ | 展示版存在本機瀏覽器；正式版會放後端資料庫 |
| AI 是真的嗎？ | 目前是規則式示範，正式版可接 AI 模型，但仍須治療師確認才儲存 |
| 能串 PAC／信祥嗎？ | 已預留獨立病人 ID 與外部識別碼欄位，串接需待 PAC 範圍確認 |
| 哪些階段需要計畫？ | 後台可設定；預設 PAC、復健病房啟用，一般復健、OPD 不啟用 |
| 舊版 DEMO 受什麼影響？ | 願望圖卡、任務、護照沿用並擴充；新增階段歷程、熟識人、計畫版本化 |
