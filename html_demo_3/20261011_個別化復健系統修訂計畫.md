### A3. 實作生活功能關聯星等

本工項為必要實作。依 `02-員郭第二次需求訪談.md` 的願望交集規則計算。

#### 計算規則

對每個生活功能項目，計算共同需要該項目的不重複願望數。同一願望對同一項目只計算一次。

| 關聯命中數 | 關聯星等 | 說明 |
|---:|---|---|
| 0 | 不顯示星等 | 不列入願望展開清單 |
| 1 | ★☆☆ | 一個願望需要此項目 |
| 2 | ★★☆ | 兩個願望共同需要此項目 |
| 3 以上 | ★★★ | 三個以上願望共同需要此項目 |

保留實際關聯命中數。三星上限只限制顯示星數。

例如：若四個願望共同需要同一項目，則顯示「★★★｜4 個願望共同需要」。

#### 顯示與排序

- 在待放置區的生活功能項目顯示關聯星等。
- 在項目旁顯示實際關聯命中數。
- 依關聯命中數由高至低排序。
- 若關聯命中數相同，則依項目編號排序。
- 在象限內保留同一項目的關聯星等。
- 加入「生活功能關聯星等說明」按鈕。
- 說明星等不是功能能力分數。
- 說明星等不是病人意願分數。

取得已選願望。展開生活功能項目。計算關聯命中數。排序生活功能項目。顯示關聯星等。

**圖 3：關聯星等計算流程**

```text
+------------------------+
| 取得已選願望           |
+------------------------+
            |
            v
+------------------------+
| 展開生活功能項目       |
+------------------------+
            |
            v
+------------------------+
| 計算關聯命中數         |
+------------------------+
            |
            v
+------------------------+
| 排序生活功能項目       |
+------------------------+
            |
            v
+------------------------+
| 顯示關聯星等           |
+------------------------+
```

#### 更新與保存

- 若新增或取消願望，則重新計算關聯星等。
- 若拖動項目，則不改變關聯命中數。
- 若項目仍有關聯命中，則保留其象限位置。
- 若項目不再有關聯命中，則清除其目前象限位置。
- 不因目前願望變更而刪除歷史計畫。
- 各畫面共用同一個關聯計算函式。

#### 驗收條件

- 一個願望命中項目時，顯示 ★☆☆。
- 兩個願望命中項目時，顯示 ★★☆。
- 三個或四個願望命中項目時，顯示 ★★★。
- 四個願望命中項目時，命中數仍顯示 4。
- 同一願望的重複對應不增加命中數。
- 新增或取消願望後，清單即時更新。
- 拖曳前後的關聯星等一致。
- 切換病人後，不混用其他病人的願望。
- 重新整理頁面後，選取資料與象限位置仍保留。

### A4. 補齊願望篩選

先初選生活願望。再共同確認最終願望。依最終願望展開生活功能項目。

- 各畫面採用同一份最終願望清單。
- 星等依最終願望計算。

### A5. 調整願望象限與病人操作模式

修訂前的象限拖曳生活願望。本次改為拖曳生活功能項目。兩者不可混為同一種資料。

在左側上方保留最終願望摘要。在待放置區顯示生活功能項目。將生活功能項目拖入象限。

另存生活功能項目的象限位置。不直接沿用生活願望的位置資料。保留舊位置資料，不強制轉換。

保留目前象限座標軸。不要因引用星等規則而自動改用舊文件的座標軸。

提供簡化的病人操作模式。隱藏主檔編輯與後台管理。保留必要圖片、文字與返回操作。保留拖曳操作。保留先點項目、再點位置的操作。

**驗收條件**

- 待放置區的項目有關聯星等。
- 象限內的同一項目保留關聯星等。
- 關聯星等不自動決定象限位置。
- 平板可完成點選與拖曳。
- 大字模式不遮蔽主要按鈕。
- 病人模式不顯示後台編輯入口。

## 7. 階段 B2：正式上線

正式上線必須串接 API。正式 API 與 PAC／HIS 外部串接是不同工項。

| 工項 | 正式要求 |
|---|---|
| 正式登入 | 驗證真正的使用者身分 |
| 後端權限 | 在 API 驗證查看與寫入權限 |
| 共享資料 | 由正式資料庫保存個案與計畫 |
| 多人寫入 | 防止多人更新互相覆蓋 |
| 資料移轉 | 驗證移轉內容。確認後才寫入 |
| 稽核紀錄 | 保留操作者、時間與變更內容 |
| PAC／HIS 串接 | 依核定欄位與責任邊界交換資料 |
| 正式 AI | 若核定納入，則接入正式模型 |

目前 AI 草稿採規則組句。規則組句不等於正式模型服務。

正式上線前，必須完成 API、權限、資料保存與多人操作驗證。不得只更換頁面標題即視為正式系統。
