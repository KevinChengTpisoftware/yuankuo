# 一、核心方向：改成「以病人為核心」

是否調整為每一位病人都有自己的主檔，再依目前照護階段決定可使用哪些功能

* 每位病人都建立「熟識人」資料  
* 每位病人都可以選擇生活復健任務  
* 只有特定照護階段需要進一步建立短期／長期復健計畫  
* 同一位病人在不同時間可能轉換照護階段，因此需保留歷程，不建議把類別做成固定不變的「身分」

# 二、照護階段／服務類型與路徑差異

目前預計先有以下四種照護階段類型：

* PAC 復健病人  
* 復健病房病人  
* 一般復健病人  
* OPD 病人

系統名稱是否使用「目前照護階段」或「服務類型」，因為同一位病人可能隨治療階段改變，例如一般復健後轉為 OPD，或其他階段再進入 PAC

舉例：

> 陳小姐  
> 6/1–6/30｜復健病房  
> 7/1–8/15｜一般復健  
> 8/16 起｜OPD

病人還是同一人、熟識人資料也還是同一份，只是**照護階段改變**。且希望系統不把舊的類別蓋掉，要留歷程，以下為後續路徑差異，**是否讓治療師可以選擇是產出復健計畫？**

| :---- | ----- | ----- |
| PAC | V | V |
| 復健病房 | V | V |
| 一般復健 | V |  |

# 三、「熟識人」模組

希望把目前分散的熟識人內容，整合進此系統，讓不同職類的醫師，都能在同一位病人的主檔內共同填寫、查看與更新：

* 共同資料可包含：基本資料、醫療／疾病資訊、目前功能與行動狀況、營養／飲食、照顧者與主要醫療決定者、社會心理與家庭、病前生活／興趣、居住環境等  
* 跨專業職類先包含：物理治療 PT、職能治療 OT、語言治療 ST、臨床營養 Dietitian、主治醫師 Dr.、專責護理 Nurse、社工／出院準備  
* 每個職類希望有各自對應的填寫區，而不是全部塞在同一個大文字框  
* 各職類實際固定欄位仍需再由各專業確認  
* 希望可以保留填寫者、更新時間與歷次內容，方便多人共同使用

# 四、生活復健任務（１５０項任務）-長短期調整

＊所有人都可以使用全部任務  
＊關於後台長短期設定：  
原：在後台設定每個任務的長短期  
調整為：讓治療師們自己選擇那個任務的長短期  
(因為相同任務對不同病人的難度與時間點不同，因此短／長期希望調整為，在建立個別病人復健計畫時再決定)

# 五、復健計畫與定期檢討

目前只有 PAC 與復健病房病人需要進一步建立短期／長期復健計畫

* 治療師針對該病人已選的任務，再判斷哪些屬於近期目標、哪些屬於較長期目標  
* 復健計畫約每 2～3 週需重新檢視或調整  
* 每次調整需保留版本／歷程，不直接覆蓋原本計畫  
* 一般復健與 OPD 病人，選完生活復健任務後即可完成該次紀錄，目前不需要強制產生短／長期復健計畫

# 六、病人基本資料與未來醫療系統串接

現階段病人資料會先由院內人員手動建立。未來預計與資策會那邊的系統串接(PAC、信祥)，可能透過病歷號及其他病人識別資料，自動帶入姓名與基本資料（？）  
因此希望目前資料架構先保留未來串接的彈性，例如：系統內有獨立病人 ID，並可對應院內病歷號／外部系統識別碼，避免未來串接時需要重做病人主檔
