# 復健學習護照互動系統 - 開發者交接說明 (Handover Document)

本文件旨在提供後續接手開發者（如夏禕葛開發者）快速了解系統架構、技術選型、資料結構及部署啟動方式。
本文件已排除所有私密 API 金鑰與敏感認證資訊，可安全作為交接使用。

---

## 1. 專案概述 (Project Overview)

* **系統定位**：專門為醫療照護與復健臨床設計的「互動式學習護照」，支援病患個人化任務解鎖、生活願望探索、六大生活功能評估與進度追蹤。
* **主要終端**：RWD 響應式網頁，主要運行於平板電腦（iPad / Android 平板）、智慧型手機與病房工作站電腦。
* **核心模組**：
  1. **復健護照主介面**：依階段分層任務清單、自立/夥伴協同標記、語音旁白朗讀與成就解鎖音效。
  2. **成效分析與雷達圖**：六大維度生活功能即時雷達圖 (Recharts)、各階段達成率統計。
  3. **生活願望清單 (Wishlist)**：28 張高解析度願望圖卡選擇與客製化目標設定。
  4. **跨個案管理後台 (Admin Dashboard)**：病患名冊管理、個案進度追蹤、報表匯總預覽與 CSV 匯出。
  5. **雙軌權限登入系統**：臨床工作人員 6 位數 PIN 碼登入與最高管理員權限控制。

## 3. 資料庫結構與模型 (Database Schema)

目前系統使用 NoSQL 文件型資料庫（Firestore），由兩大主集合構成：

### (1) 個案集合：`/patients/{patientId}`
儲存病患個人化資料與復健歷程：
* `id`: 個案唯一代碼 (string)
* `caseNumber`: 病歷號/個案編號 (string)
* `name`: 個案姓名 (string)
* `status`: 狀態 (string，如 `'active'` 進行中、`'completed'` 已結案)
* `primaryTherapist`: 主責治療師或照護員姓名 (string)
* `admissionDate`: 收案日期 (string)
* `targetDate`: 預計完成日 (string)
* `notes`: 照護註記與備忘 (string)
* `completedTasks`: 已解鎖任務代碼清單 (string[])
* `taskPartners`: 各任務之協同夥伴紀錄 (Record<taskId, partnerName>)
* `taskCompletedAt`: 任務解鎖之精確時間戳記紀錄 (Record<taskId, ISOString>)，用於臨床時間序追蹤與檢核報告匯出
* `unlockedBadges`: 已獲得徽章與解鎖時間 (Record<badgeId, dateString>)
* `selectedWishes`: 已挑選的生活願望卡片 (string[])
* `customWishes`: 自訂願望紀錄 (object[])
* `createdAt` / `updatedAt`: 建立與最後異動時間戳記 (string)

### (2) 臨床人員名冊集合：`/staff/{staffId}`
儲存臨床人員基本資訊與身分驗證資料：
* `id`: 人員識別碼 (string)
* `name`: 人員姓名 (string)
* `title`: 專業職稱（例如：物理治療師、職能治療師、護理師、照服員） (string)
* `pin`: 6 位數登入 PIN 碼 (string)
* `isActive`: 是否啟用 (boolean)
* `createdAt` / `lastLoginAt`: 建立時間與最後登入紀錄 (string)
* `notes`: 備註資訊 (string)

> 註：根目錄下的 `firebase-blueprint.json` 包含詳細的資料模型規格，`firestore.rules` 為目前的存取控制規則。

## 5. 本機開發與啟動步驟 (Local Development)

### 步驟一：安裝依賴套件
確認本機已安裝 Node.js (建議 v18 以上)：
```bash
npm install
```

### 步驟二：環境變數設定
請在專案根目錄建立 `.env.local` 或 `.env` 檔案，填入相應的 Firebase 設定（請洽管理員提供或替換為院內專屬配置）：
```env
VITE_FIREBASE_API_KEY=YOUR_FIREBASE_API_KEY
VITE_FIREBASE_AUTH_DOMAIN=YOUR_PROJECT_ID.firebaseapp.com
VITE_FIREBASE_PROJECT_ID=YOUR_PROJECT_ID
VITE_FIREBASE_STORAGE_BUCKET=YOUR_PROJECT_ID.firebasestorage.app
VITE_FIREBASE_MESSAGING_SENDER_ID=YOUR_MESSAGING_SENDER_ID
VITE_FIREBASE_APP_ID=YOUR_APP_ID
```

### 步驟三：啟動開發伺服器
```bash
npm run dev
```
瀏覽器開啟終端機顯示的 URL（通常為 `http://localhost:3000` 或 `http://localhost:5173`）即可進行預覽與測試。

### 步驟四：生產環境打包 (Production Build)
```bash
npm run build
```
打包完成後會產出 `dist/` 目錄，可直接交付院內 Nginx、IIS 或容器化環境靜態託管。

## 7. 後續醫療場域落地建議（給接手開發者的評估事項）

考量醫療機構對病人隱私法規（個資法、病歷法規）與內網隔離需求，若未來不採用外網雲端服務，建議評估以下兩種改造途徑：

1. **純前端離線運行版 (IndexedDB / Local Database)**：
   * 將 `src/services/patientService.ts` 與 `src/services/authService.ts` 的資料存取邏輯，由 Firestore 改寫為瀏覽器端資料庫（如 `idb` 或 `dexie`）。
   * 擴充「全資料庫 JSON 一鍵備份與匯入還原」功能，各病房平板即可在無連網狀態下獨立運作。
2. **院內私有伺服器部署 (On-Premises / Docker + SQLite or PostgreSQL)**：
   * 保留目前的 RESTful / WebSocket API 接口，改接院內私有伺服器後端，符合院內機房落地與資訊安全稽核標準。
